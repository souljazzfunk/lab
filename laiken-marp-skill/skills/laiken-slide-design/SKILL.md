# laiken-light のデザインバランス

会場の一番後ろの席から、2秒で読めること。デザインの判断はすべてこれに従う（`laiken-slide-story` の大原則）。

このスキルは、みのるん（[@minorun365](https://x.com/minorun365)）の黒地テーマ用の規則（[minorun-marp-skill](https://github.com/minorun365/minorun-marp-skill) の slide-design-dark）を、らいけんの明るいテーマ向けに改造したもの。テーマ本体は `theme/laiken-light.css`、検査スクリプトは `tools/` にある。

## テーマの基本

```markdown
---
marp: true
paginate: true
theme: laiken-light
---
```

| クラス | 用途 |
|---|---|
| `top` | 表紙。中央寄せ、タイトルの下にアクセント色の短い帯、ページ番号なし。名前は `らいけん（X: @thunder_bark）` |
| `crosshead` | 中扉。淡い地 `#efe9e2`、上下中央、ページ番号なし |
| `image-full` | 見出しと大きな画像 |
| `split` | 左に本文、右に画像。`![bg right:40% contain]` と組み合わせる |

- `**太字**` はアクセント色（唐辛子の深紅）、`*斜体*` は斜体にせず、サブアクセントの太字で表示される
- 共用のテーマCSSは書き換えない。資料ごとの調整は、フロントマター直後の `<style>` か、そのスライドだけの `<style scoped>` に書く
- 書体はサンセリフだけ。macOS はヒラギノ角ゴ、Windows は游ゴシック、Linux は Noto Sans CJK で出る。明朝や丸ゴシックを足さない

## 文字サイズ

換算は 1pt = 1.333px（1280×720 の版面）。

| 用途 | サイズ |
|---|---|
| 本文、箇条書き（既定） | **36pt（48px）** |
| h1（スライドの見出し） | 45pt（60px） |
| 表紙の h1 | 57pt（76px） |
| 中扉の h1 | 50pt |
| h2、入れ子の箇条書き、表紙の名前 | 30pt（40px） |
| 表、コード、キャプション、出典の注記 | 24pt（32px）＝下限 |

- **24pt 未満は禁止**。CSSにも `<style scoped>` にもSVGにも書かない。例外はページ番号だけ
- 収まらないときに、フォントサイズを下げない。文字を削るか2枚に割る。1スライドだけ文字が小さいと、通しで見たときに不揃いとして出る

## 1スライドに入る量

版面は1280×720、padding は上52・左右68・下64px。本文に使える幅は1144px。h1 は下線と余白を含めて約104pxを使うので、本文に使える高さは約500px。

| 構成 | 上限 |
|---|---|
| 文字だけ | 箇条書き4行まで（推奨2〜3行）。1項目20文字以内 |
| 大きな図＋文字 | 図の viewBox 高さ340＋2行、または260＋3行 |
| 図だけ | 図の viewBox 高さ480まで |
| 表 | ヘッダ＋本文5行まで |

日本語は48pxで1行あたり約22文字。1項目20文字以内なら折り返さない。

## 余白は測ってから決める

「もう少し上へ」「余白をあけて」と言われて、値を勘で足し引きしない。根拠の無い数字で触ると、直したつもりの箇所が別の要素とぶつかり、同じ指摘を何巡も受ける。

```bash
mutool draw -F stext -o - deck.pdf | grep '<line bbox='   # 本文の行ごとの位置
```

塗りの面（ボックスや帯）はテキスト抽出に出ないので、ページを画像に焼いて色の連なりから取る。測ったら、位置を足し算ではなく規則で決める。

- 横位置は、スライドの中央か、本文の左端に揃える。本文の左右余白より外へ出さない
- 縦位置は、本文の下端からスライド下端までの空きの縦中央に置く
- 要素どうしは30px以上あける

PDFの座標は960×540、MarpのCSSは1280×720が基準なので、係数0.75を掛けて換算する。

素材を差し替えただけで見せない。図や写真を入れ替えたら、同じ作業のなかで幅、四方の余白、見出しとの間隔、隣の要素との重なりまで整える。

## 縦のバランス

- 本文は見出しの直下から始める。本文が短くて下が空いても、それが普通の形である。見出しと本文のあいだを広げて中央に見せる組み方はしない
- 図が主役のスライドだけは、図を見出しの直下に貼らない。図の上に36px以上（見本デッキは48px）を取る
- 本文の下に画像や表が来て、その下に何も無いスライドは、画像の上の空きと下の空きを等しくする。上下の空きを実測し、差が6pxを超えたら `position: relative; top: <差の半分>px` で下げる
- Marpの `section` は `display: block` なので、`margin: auto 0` では縦中央に寄らない
- 箇条書きの直後に締めの文が続くスライドは、テーマが40pxあける（`ul + p`）。自分で `<br>` を足さない
- 1語だけが次の行に落ちる折り返しは、全部つぶす。読点や句点の位置で自分で改行するか、文言を削る。Marpは素の改行がそのまま反映される
- 見出しと似た表現の箱を、見出しの直下に置かない。同じことを2回言っているように見える

デザインの直し方を発明しない。バランスが悪いと言われたら、まず同じ構成のスライドを過去のデッキから探して真似る。新しいCSSの型を作るのは最後の手段で、作るなら先に1スライドだけ試して見せる。

## 配色

パレットの外の色を足さない。

| 用途 | 色 | 地 `#f8f6f1` とのコントラスト比 |
|---|---|---|
| 本文 | `#241e1c` | 15.2 |
| 入れ子の箇条書き、表紙の名前 | `#473b36` | 10.0 |
| アクセント：唐辛子（強調、主役の面、リンク） | `#9e2f28` | 6.7 |
| 補足の文字 | `#655b55` | 6.1 |
| サブアクセント：カルダモン（h2、キャプション） | `#56704f` | 5.1 |
| 差し色：カルダモン（見出しの下線、箇条書きの点、表紙の帯） | `#7c9a6e` | 2.9 |
| 矢印 | `#ad9f94` | 2.4 |
| 罫線、箱の枠 | `#dcd1c6` | 1.4 |
| 淡い面（中扉の地、表のヘッダ） | `#efe9e2` | 1.1 |

### 明るい地で沈むかはコントラスト比で測れる

```python
def lin(c):
    c /= 255
    return c/12.92 if c <= 0.03928 else ((c+0.055)/1.055)**2.4
def L(h):
    h = h.lstrip('#'); r,g,b = (int(h[i:i+2],16) for i in (0,2,4))
    return 0.2126*lin(r) + 0.7152*lin(g) + 0.0722*lin(b)
def ratio(a, b):
    x, y = sorted([L(a), L(b)]); return (y+0.05)/(x+0.05)
ratio('#9e2f28', '#f8f6f1')   # 6.73
```

| 用途 | 地とのコントラスト比の目安 |
|---|---|
| 本文 | 7以上 |
| 32px前後の補足、キャプション | 4.5以上 |
| 40px以上の太字（見出し、強調） | 3以上 |
| 線、矢印 | 2〜3 |
| 箱の枠 | 1.3〜1.6 |

アクセント `#9e2f28` は6.7あるので、32pxの小さい文字にもそのまま使える。差し色 `#7c9a6e` は2.9しかないので、文字には使わない。線、点、帯のような図形専用にする。文字をカルダモンにしたいときは、1段暗いサブアクセント `#56704f`（5.1）を使う。

### 面の暗さの下限は、上に乗る白文字が決める

アクセントの面に白文字を乗せたときの比は7.3で、32pxでも読める。面の中で主従の差をつけたいときは、補足を白ではなく `#f3d2cc`（5.2）にする。面をもっと明るくしたい、という要望は白文字と両立しない。数字で示してから文字色を変える案を出す。

### 同じ色でも、面は明るく、線は暗く見える

黒地とは逆に、明るい地では細い線と小さい文字が薄く飛ぶ。同じ色を面と細い文字の両方に使って「文字だけ薄い」と言われたら、文字と線に使う色を面の色より1段暗くする。

### 2色が喧嘩する原因は、色相よりトーン

色相環の距離だけで判断しない。明度と彩度が揃っていないほうが、原因として多い。直す順番は、まず明度と彩度を相手に寄せる、それでも駄目なら色相を離す、である。色相を動かすと色の意味まで変わるので、最後の手段にする。

### メリハリは色を足さず、主役以外を落とす

表や図がのっぺりして見えるなら、全部が本文色になっている。主役の色は動かさず、見出し、罫線、ラベルのほうを落として段差を作る。1.5倍以内の差では変えた気がしない。会場のプロジェクタは明るい色が飛ぶので、枠や罫線を `#dcd1c6` より薄くしない。

### 製品を紹介するデッキは、その製品のブランド色を使う

公式サイトのCSSから色コードを取る。ブランド色をそのまま小さい文字に使うと明るい地では読みづらいので、コントラスト比を測って用途で明度を変える。表紙の帯と主役の面は、ブランド色そのままでよい。

### 候補は実物のページに当てて見せる

色見本や数字だけでは決まらない。同じページを候補の数だけ書き出して、2×2のグリッドに並べる。本文の強調が乗るスライドと、図の中で使われるスライドの2つで比べる。

### 色の一括置換

「気にしない色」を除外条件にした検索を使わない。置き換える色そのもので探し、置換後に旧色が0件になることを確かめる。SVGに残りやすい。

```bash
grep -rn -i '#9e2f28\|#56704f' deck.md images/*.svg
```

## 強調

- 1スライドに1か所まで。デッキ全体では、本文2〜3スライドに1か所。残すのは各パートのパンチライン（締めの一言、鍵になる数字）だけ
- 数字を3つ並べるスライドは、次のスライドへつながる1つだけを塗る
- 表のセルの中で `**太字**` を使わない。セルの地があるので、アクセント色が濁る

## 確定デザイン

### 表

テーマの既定で、罫線 `#dcd1c6`、ヘッダは淡い地にサブアクセントの文字、1列目は太字、偶数行に薄い縞が入る。

- ヘッダ＋本文5行まで。超えるなら図にするか、巻末の参考資料へ回す
- セルは1行に収める。はみ出したら文言を削る。自動の折り返しに任せると、最後の1文字だけが2行目に落ちる
- 注目させる行は、アクセントの薄い網掛け（`rgba(158,47,40,.10)`）で1行だけ
- 表の下に小さい注記を置かない

### コード

テーマの既定で、白地に3pxの枠、角丸18px、24pt。

- 24ptが下限。1行は半角50文字まで。収まらないなら行を分けるか文言を削る
- サンプルは1つに絞り、1行に1つのことを書く
- 箱の下端は、ページの下端から60px以上あける

### 補足ボックス

本文の下の空きへ、淡い面の角丸ボックスを置き、補足の1行を入れる型。

```css
.gbox { position: absolute; left: 0; right: 0; margin: 0 auto;
        width: fit-content; min-width: 900px; max-width: 1144px;
        bottom: 64px; background: #efe9e2; border: 3px solid #dcd1c6;
        border-radius: 18px; padding: 16px 56px; text-align: center; }
.gbox, .gbox p { font-size: 32pt; line-height: 1.35; }
.gbox p { margin: 0; }
.gbox.key { background: #9e2f28; border-color: #9e2f28; }   /* 結論のパンチライン */
.gbox.key, .gbox.key p { color: #ffffff; font-weight: 700; }
```

- `left:50%` と `translateX(-50%)` で中央に寄せない。使える幅が画面の右半分だけになり、収まるはずの文が折り返す
- `font-size` は `.gbox` と `.gbox p` の両方に当てる。div の中のMarkdownは `<p>` が生成されないことがある
- 引用や話しかけの例は淡い面、結論のパンチラインはアクセントのベタ塗りに白抜き。全部を同じ塗りにしない

### 比較のスライドは大きい数字を2つだけ

「0.35秒と1.34秒」のような比較は、数字を88ptで2つ並べ、下に1行。細い縦線1本で左右を分ければ足りる。

### 図のラベルは箱の外の上に置く

箱の中には中身だけを入れる。箱が何であるかの名前は、箱の上14pxに32pxで置く。

### スクリーンショット

`![bg right:40%]` で置くと右端に密着する。`![w:900 center]` で中央に置き、`border-radius:14px` と `#dcd1c6` の1px枠を掛ける。明るい地の上では、白いスクリーンショットの縁が地と溶けるので、枠は必須。2枚を左右に並べるときは、縦横比を揃える。

### 見せ方のリズム

- 文章のスライドが5つ続くと単調になる。中扉、図だけのスライド、スクリーンショットの中央置きを混ぜる
- 同じ型の図のスライドが6つ続くのも同じ。図のスライドと、文章のスライドを交互にする

## Marp固有の罠

- 全角の開き括弧（「『（）に隣接する `**強調**` は反映されず、アスタリスクがそのまま出る。`<strong>` で書く。書き出したPDFで確かめる

  ```bash
  mutool draw -F stext -o - deck.pdf | grep -c 'c="\*"'   # 0 が正常
  ```

- div の中でMarkdownの強調を反映させるには、開きタグの直後と閉じタグの直前に空行を入れる
- `</div>` の直後に空行なしで `---` を書くと、スライドの区切りとして認識されず、ページが1つ減る
- `<img>` のインライン `style` 属性は落とされる。クラスで書く
- default テーマの表のセルは `section table th` の詳細度で padding が当たる。上書きするときは `section table ...` から書く
- mdを `\n---\n` で分割すると、先頭はフロントマターになる。最初のスライドは2番目の要素で、そこにはデッキ全体の `<style>` が同居していることが多い。表紙を作り直すつもりで丸ごと置き換えると、全ページのスタイルが消える
- スクリプトでスライドを削除や挿入するときは、番号の降順で処理する。実行前に、対象の中身を `assert` で確かめる
- 「p36を直して」のpは、書き出したPDFのページ番号である。原稿の `---` を数えて対応付けると、フロントマターの区切りの分だけずれる。そのページだけ画像に焼き、写っている文言で原稿を検索して直す

  ```bash
  pdftoppm -png -r 80 -f 36 -l 36 deck.pdf /tmp/p36
  ```

- 発表者ノートは、ディレクティブ以外のHTMLコメント（`<!-- 話すこと -->`）に書く。`key: value` の形はディレクティブとして読まれることがあるので避ける

## 書き出したら検査する

Marpは、版面からコンテンツがあふれてもエラーを出さない。書き出すたびに検査を通す。

```bash
marp --no-stdin deck.md --pdf --theme theme/laiken-light.css --allow-local-files

python3 tools/check-margins.py deck.pdf           # 中身の下端と右端の空き。60px未満でNG
python3 tools/check-gaps.py deck.pdf              # 画像、図、コードの箱と隣の本文の間隔。36px未満でNG
python3 tools/check-figure-text.py deck.pdf       # 24pt未満の文字、箱の縁まで14px未満の文字
node tools/check-svg-box-fit.mjs images/*.svg     # SVGを描画して文字と枠の余白を実測
```

Claude Code のクラウド環境では、Marp の書き出しに `CHROME_PATH=/opt/pw-browsers/chromium` を付ける。

検査スクリプトは、ページごとに左上隅の色を「地」として取り、地と違う画素を中身とみなす。表紙のようにグラデーションの地のページは `check-margins.py` の対象外になる。

NGは全件を列挙してから要約する。先に要約すると、3件目を見落とす。

### 機械検査のあとに、自分の目で見る

検査が全部OKでも、目視は省けない。検査は存在する要素を測る仕組みなので、要素が丸ごと描かれなかった崩れは1つも検出できない。検査OKの報告と、目視の報告は分けて書く。

```bash
pdftoppm -png -r 55 deck.pdf /tmp/all/p    # 全ページを小さく焼き、数ページずつ貼り合わせて順に見る
```

目視でしか捕まらないものは、文字と挿絵や図形の重なり、下方向の余白のつぶれ、矢印の軸が隠れて矢尻しか見えない状態、見出しの大きさや位置のページ間の不揃い、不自然な改行、挿絵の入れ忘れである。

吹き出しのしっぽ、矢印、帯のように、別の図形を要素の上に重ねたものは、縮小した全ページ画像では合格に見える。重ねたページだけ高解像度で焼き直し、付け根の周囲を拡大して見る。

```bash
mutool draw -r 200 -o hi.png deck.pdf 2
```

1ページを直したら、同じ観点で全ページを点検してから報告する。1ページの指摘は、そのページの指摘ではなく検査の指示である。同じ条件を全ページに機械で当て、一覧を出してから直す。直したら同じ検査をもう一度全ページに当て、0件になったことを報告に書く。
