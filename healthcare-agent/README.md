# ヘルスケア医師案内エージェント（CLI・クローズド構成）

患者・家族からのメッセージ／音声（文字起こし済みテキスト）を受け、`sample_doctors.json` から最適な医師を案内する CLI エージェント。

## 設計方針
- **クローズド**: 外部 API・ネットワーク通信なし。標準ライブラリだけで動く。ログはローカル保存のみで、電話番号・メール・日付・患者 ID はマスクしてから書き込む。
- **レガシー対応**: 検索 API は使わない。起動時に JSON を 1 回だけ読み込み、メモリ上にインデックスを作る。
- **安全第一**: 緊急ワード（胸の締め付け、呼吸困難など）は検索より先に判定し、119 / #7119 を案内する。

## KPI への効き方
| KPI | 施策 |
|---|---|
| CSAT | 症状から診療科を推定（例: 頭痛 → 神経内科、子ども → 小児科）／希望条件（性別・言語・曜日・オンライン）に合う医師が 0 件なら条件を緩めて理由も伝える／新患受付停止中の医師は順位を下げる／会話の終わりに 1〜5 で評価を取る |
| SLA | ローカルのメモリ検索なので一次応答はミリ秒単位。チャネル別の SLA 目標（voice 1 秒 / message 3 秒）に対する達成率を記録する |
| 処理 Ticket 数 | 全問い合わせをチケット化し、`batch` で一括処理できる。医師案内以外の用件（請求など）は受付番号つきで即エスカレーション。症状が曖昧なときは 1 回だけ聞き返し、その文脈を引き継ぐ |
| Voice 対応 | 音声チャネルは 1 名を 1 文で案内する（通話時間を短く） |

## 使い方
```bash
python3 agent.py chat --channel voice          # 対話（終了時に CSAT）
python3 agent.py ask "英語が話せる循環器の先生"   # 単発
python3 agent.py batch samples/inquiries.jsonl  # 一括処理
python3 agent.py metrics                        # 処理 Ticket 数 / 自動解決率 / SLA / CSAT
python3 agent.py --data /path/to/sample_doctors.json chat   # 本番データ
```

## 構成
- `core.py`: 意図判定・条件の抽出（緊急／医師名／対象外／検索／不明）、医師インデックスとスコアリング、PII マスク
- `agent.py`: CLI、チケット管理、KPI 集計（時刻は JST）
